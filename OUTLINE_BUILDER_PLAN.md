# Outline Builder → Course Content Pipeline — Implementation Plan

## Overview

The Outline Builder is a content authoring tool that produces **Courses** — a new first-class content type that lives alongside Pathways and Specializations under the "Curriculum" section. Users build a hierarchical outline in the browser, link outline nodes to existing site content (lessons, lectures, exercises, etc.), and then **generate** the Course as Decap CMS-compatible markdown files that are committed back to the repository.

This bridges the gap between Decap CMS (which has no native hierarchy builder) and the structured course content the site needs. The Outline Builder is the *authoring UI*; the resulting Course pages are standard markdown content with the same versioning, OER Schema, and Common Cartridge export capabilities as Pathways and Specializations.

### How It Fits the Current Architecture

```
Current hierarchy:
  Pathway  (oer:Course)  →  Specialization  (oer:LearningComponent)  →  Lesson  →  Items

New addition:
  Course   (oer:Course / oer:Syllabus)  →  Modules (sections)  →  linked Items
  ↑ authored via Outline Builder         ↑ stored as frontmatter    ↑ references to existing content
```

**Key distinction from Pathways:** Pathways reference *specializations* which reference *lessons*. Courses reference content items *directly* in an author-defined order — they're more like a syllabus or a custom playlist of existing materials, with optional free-text module groupings.

The **critical design choice** is storing the outline hierarchy in frontmatter `modules[]` — each module has a title, description, and an array of `{ slug, type }` references to existing content. This makes it fully Decap CMS-editable after generation.

### 1.3 Decap CMS Collection (`public/admin/config.yml`)

Add a `courses` collection following the exact patterns of existing collections:

```yaml
- name: courses
  label: Courses
  folder: content/courses
  create: true
  extension: md
  format: frontmatter
  identifier_field: title
  nested:
    depth: 100
  meta: { path: { widget: string, label: Path, index_file: index } }
  view_filters:
    - { label: Published, field: published, pattern: true }
    - { label: Unpublished, field: published, pattern: false }
  fields:
    # ... standard fields (title, slug, date, type, description, published, etc.)
    # ... version fields
    - name: modules
      label: Modules
      widget: list
      fields:
        - { name: title, label: Title, widget: string }
        - { name: description, label: Description, widget: text, required: false }
        - name: items
          label: Items
          widget: list
          fields:
            - { name: slug, label: Slug, widget: string }
            - name: type
              label: Type
              widget: select
              options: [lesson, lecture, tutorial, article, exercise, project]
    # ... learningObjectives, duration, difficulty, license, oer schema, etc.
```

This means **after** the Outline Builder generates a course, instructors can also edit it directly in Decap CMS — adding/removing modules and items via the familiar list widgets. The Outline Builder is the *better* authoring experience for initial creation, but Decap handles ongoing edits.

## Phase 2 — Outline Builder Core (Authoring UI)

**Goal:** Replace the placeholder page with a working outline editor that builds course structures.

### 2.1 Composable: `useOutlineBuilder.ts`

Manages the in-progress outline before it becomes a Course:

```
OutlineItem {
  id: string              // crypto.randomUUID()
  text: string            // section/module title or free text
  note: string            // optional description
  depth: number           // 0 = module, 1 = item within module (max 2 levels)
  linkedContent?: {       // link to existing content
    slug: string
    type: 'lesson' | 'lecture' | 'tutorial' | 'article' | 'exercise' | 'project'
    title: string
    description?: string
  }
}

OutlineDraft {
  id: string
  title: string           // becomes Course title
  description: string     // becomes Course description
  author: string
  license: string
  difficulty: string
  learningObjectives: string[]
  items: OutlineItem[]    // flat list with depth
  createdAt: string
  updatedAt: string
}
```

**Depth mapping to course structure:**
- Depth 0 → **Module** (section heading in the course)
- Depth 1 → **Item** within a module (linked content reference)

Keeping this to 2 levels matches how courses actually work (modules contain items) and keeps the UI simple.

**State & methods:**

| Method | Description |
|---|---|
| `addItem(afterId?, depth?)` | Insert a new blank item |
| `removeItem(id)` | Delete item |
| `updateItem(id, patch)` | Update text, note, depth, or linkedContent |
| `indent(id)` | Promote to child (depth 0→1) |
| `outdent(id)` | Promote to module (depth 1→0, clears linkedContent) |
| `moveUp(id)` / `moveDown(id)` | Reorder in flat list |
| `reorder(fromIndex, toIndex)` | Drag-and-drop reorder |
| `toModules()` | Convert flat list → `modules[]` structure for frontmatter |
| `drafts` | List of saved drafts in localStorage |
| `saveDraft()` / `loadDraft(id)` / `deleteDraft(id)` | Draft management |

**Persistence:** `localStorage` via `@vueuse/core`'s `useLocalStorage`, auto-saving on change.

## Phase 4 — Course Generation (The Key Phase)

**Goal:** Convert the outline into Decap CMS-compatible markdown and commit it to the repository.

This is where the Outline Builder becomes more than a standalone tool — it writes content back into the site.

### 4.1 Composable: `useCourseGenerator.ts`

```ts
export function useCourseGenerator() {
  return {
    generateMarkdown(draft: OutlineDraft): string       // full .md file with frontmatter
    generateOERSchema(draft: OutlineDraft): object       // oer:Course JSON-LD
    previewCourse(draft: OutlineDraft): CoursePreview     // structured preview before committing
    downloadAsFile(draft: OutlineDraft): void             // download .md to disk
    commitToRepo(draft: OutlineDraft): Promise<void>      // push via GitHub API (if authenticated)
  }
}
```

### 4.2 Generation Flow

```
OutlineDraft (in-browser state)
       │
       ▼
  ┌─────────────┐
  │ toModules()  │  Convert flat items → modules[] structure
  └──────┬──────┘
         │
         ▼
  ┌──────────────────┐
  │ generateMarkdown │  Build YAML frontmatter + markdown body
  └──────┬───────────┘
         │
         ▼
  ┌──────────────────────────┐
  │ Output: index.md         │  Complete Decap-compatible file
  │ Path: content/courses/   │
  │        {slug}/index.md   │
  └──────────────────────────┘
         │
         ▼
  How to get it into the repo?
  ┌─────────────────────────────────────────────┐
  │ Option A: Download .md file → user manually │
  │           adds to repo (always available)   │
  │                                             │
  │ Option B: Copy to clipboard → paste into    │
  │           Decap CMS raw editor              │
  │                                             │
  │ Option C: GitHub API → create file directly │
  │           in repo via commit (auth required)│
  └─────────────────────────────────────────────┘
```

### 4.3 Option A — File Download (No Auth Required)

The simplest path. The generator produces the `.md` file content and triggers a browser download:

```
intro-to-3d-modeling/
  index.md    ← downloaded file
```

The user then places this file in `content/courses/` in their repo. This works for any user, no authentication needed, and matches how people already work with static site content.

### 4.4 Option B — Clipboard Copy

"Copy Frontmatter" button copies the generated YAML + markdown to the clipboard. User can paste it into Decap CMS's raw markdown editor for a new course entry, or into a file in their editor.

### 4.5 Option C — Direct GitHub Commit (Auth Required)

For users who are authenticated via Netlify Identity / GitHub OAuth (which Decap CMS already provides), the Outline Builder can commit the file directly:

1. Check if user is authenticated via Decap's auth (Netlify Identity).
2. Use the GitHub Contents API (`PUT /repos/:owner/:repo/contents/:path`) to create the file.
3. This triggers a Netlify rebuild, and the course appears on the site.

This is the most seamless path but requires the user to be logged in. The implementation can be phased — start with Option A, add Option C later.

### 4.6 Preview Before Generating

Before committing/downloading, show a preview:
- Rendered course page (using the same layout as `pages/courses/[...slug].vue`)
- Raw markdown view (toggleable)
- Validation warnings (e.g., empty modules, unlinked items, missing metadata)

## Phase 6 — Versioning & Lifecycle

**Goal:** Courses support the same version workflow as other content types.

### 6.1 Version Support

Since courses are standard markdown files in `content/courses/{slug}/`, the existing versioning system applies directly:

```
content/courses/intro-to-3d-modeling/
  index.md          ← v1.1.0 (latest, editable)
  v/
    1.0.0.md        ← archived snapshot
```

- `useContentVersions('courses')` works with no changes if 'courses' is added to the type union.
- Version badge and dropdown in the course detail page work via existing `<VersionsDropdown>` component.
- The Outline Builder's "Generate" action always creates `index.md` (latest version).
- Creating a version snapshot (copying to `v/1.0.0.md`) follows the existing manual or scripted process.

### 6.2 Editing Existing Courses in the Outline Builder

Allow the Outline Builder to **import** an existing course back for editing:

1. "Edit in Outline Builder" button on course detail pages.
2. Fetches the course's frontmatter, converts `modules[]` back into the flat `OutlineItem[]` format.
3. User edits in the builder, then re-generates (bumping the version).

This round-trip (`markdown → outline → edited markdown`) makes the builder useful beyond initial creation.

## Technical Decisions

| Decision | Choice | Rationale |
|---|---|---|
| **Course data model** | `modules[]` array in frontmatter | Decap CMS can edit it via nested list widgets; queryable by Nuxt Content; simple flat YAML |
| **Outline depth** | Max 2 levels (module → item) | Matches real course structure; avoids Decap CMS deeply-nested list complexity |
| **OER type** | `oer:Course` (same as Pathway) | Semantically correct; distinguished from Pathways by the `modules` structure |
| **Content references** | `{ slug, type }` pairs | Lightweight; resolved at render time; same pattern as specialization→lesson references |
| **Generation output** | Standard `.md` with YAML frontmatter | 100% Decap CMS compatible; no special format needed |
| **Getting content into repo** | Download first, GitHub API later | Progressive enhancement; download works for everyone |
| **Draft persistence** | `localStorage` via `useLocalStorage` | No backend needed for drafts; course files are the permanent store |
| **Drag-and-drop** | `vuedraggable@next` | Battle-tested SortableJS wrapper for Vue 3 |
